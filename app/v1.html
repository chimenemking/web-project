Concept 01

Semantic HTML

Semantic elements describe what content is, not just how it looks. A <nav> tells browsers and screen readers "this is navigation." A <div> tells them nothing. The three cards below use the correct tags — <article>, <header>, <h3>, <p> — so search engines and assistive tech understand them without any extra hint.

<article>

Use landmark tags

<header>, <nav>, <main>, <aside>, <footer> create a "landmark tree" that screen-reader users can jump between with a single key.

<h1>–<h6>

Heading hierarchy

One <h1> per page, then <h2> for sections, <h3> for subsections. Never skip levels — the outline is how document structure is exposed.

<button>

Buttons vs. links

If it navigates to a URL, use <a href>. If it triggers an action on the page, use <button>. Screen readers and keyboards behave differently for each.

Peek under the hood — the markup of the card you're reading 
<article class="sem-card">
  <span class="sem-card__tag">&lt;article&gt;</span>
  <h3>Use landmark tags</h3>
  <p>...</p>
</article>

Concept 02

Responsive images with srcset

One image, many files. The browser picks the right resolution for the current screen so a phone doesn't download a 4K JPEG. <picture> + srcset + sizes is the modern trio. Resize your window and watch the URL change in DevTools → Network.

srcset · sizes · <picture>
Peek under the hood — the picture element 
<picture>
  <source media="(max-width:744px)"
          srcset="img-744.jpg 744w, img-1488.jpg 1488w">
  <source media="(max-width:1440px)"
          srcset="img-1440.jpg 1440w, img-2880.jpg 2880w">
  <img src="img-1920.jpg" alt="..." loading="lazy">
</picture>

Concept 03

CSS Grid

Grid is for two-dimensional layout — rows and columns. You define tracks on the parent, then let children flow or span into them. Below is a 4-column grid where the first tile stretches across 2 columns and 2 rows. grid-column: span 2 is doing all the work.

Concept 04

Flexbox

Flexbox is for one-dimensional layout — a row or a column. You define alignment on the parent with justify-content (main axis) and align-items (cross axis). The pills below are centred and wrap when there's no room. Change justify-content in DevTools and watch them move.

flex
justify-content: center
align-items: center
wrap
gap
Peek under the hood — flex container rules 
.flex-demo {
  display: flex;
  justify-content: center; /* main axis */
  align-items: center;     /* cross axis */
  flex-wrap: wrap;
  gap: 1.2rem;
}

Concept 05

CSS custom properties

Variables in CSS are written --name: value and read with var(--name). They cascade — override one on a parent and every child inherits. That's how this entire site's colour system works. The swatches below are literally driven by the tokens in :root.

--brand-orange
--brand-green
--brand-red
--brand-blue
Peek under the hood — defining and reading tokens 
:root {
  --brand-orange: #ffac00;
  --brand-green:  #629b5c;
}
.vars-swatch {
  background: var(--brand-orange);
}

Concept 06

Forms & inputs

A form is only useful if it can be filled with a keyboard and validated by the browser. Every input below uses native HTML validation (required, type="email", minlength) plus CSS pseudo-classes like :invalid, :focus, and :not(:placeholder-shown). Type a bad email and Tab out — you'll see the red border.

Native type="email" rejects malformed values.

Native required + minlength means no JS needed to enforce.

Peek under the hood — form markup 
<form>
  <label for="email">Email</label>
  <input id="email" type="email" required>
  <button type="submit">Submit</button>
</form>

Concept 07

Media queries

A media query applies CSS only when a condition is true. Resize the window — at 900px, 640px, and 420px the highlighted pill below changes to match the breakpoint you're currently at. This is the entire mechanism behind responsive design.

> 900px · desktop ≤ 900px · tablet ≤ 640px · mobile ≤ 420px · small
Peek under the hood — one breakpoint 
@media (max-width: 900px) {
  .mq-pill[data-bp="tablet"] {
    background: #ffac00;
  }
}

Concept 08

prefers-reduced-motion

Some people experience motion sickness, vestibular disorders, or are just distracted by animation. The user-level setting is respected via a media query. The blue square below bounces — unless you've enabled "Reduce motion" in your OS. Then it stops, with no code on your part beyond the query below.

Try toggling System Settings → Accessibility → Reduce motion while this page is open. The square respects it.

Peek under the hood — the motion query 
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.01ms !important;
    transition-duration: 0.01ms !important;
  }
}
