Concept 01

What web development is

Web development is the craft of building things that people access through a browser. Every page you've ever used — your bank, your email, this one — is a collection of text files that a browser reads, interprets, and paints on screen. A web developer is someone who writes those files, decides how they behave, and connects them to servers that store and serve data.

It's not one job. It's a family of jobs: the person who designs the layout is a developer. The person who wires the login button to a database is a developer. The person who makes the site fast is a developer. They all write code in the same three languages, just with different priorities.

The end goal

A working web page

Something a stranger can open on their phone, click, fill out, and get a result from. That's the unit of work. Everything else is a means to it.

The raw materials

HTML, CSS, JavaScript

Three languages, each with one job. HTML is structure, CSS is appearance, JS is behavior. Every modern framework is built on top of them.

The other half

Servers and data

Somewhere, a computer is answering requests and remembering things. Web development includes talking to that computer — or being the person who runs it.

Peek under the hood — a full web page in 3 lines

There is no magic. The smallest possible web page is three files that a browser reads in order.

index.html — the structure: headings, paragraphs, images, buttons.
style.css — the appearance: colors, spacing, fonts.
script.js — the behavior: what happens when you click.

By the end of V1, you will have written all three by hand. By the end of V2, you'll understand every line. By the end of V3, you'll be using professional tools that organize them into larger systems.

Concept 02

How the web actually works

When you type an address and press Enter, four things happen in under a second. Understanding these four things will make everything else in your career make sense.

1 · Your browserbrowser
→
2 · DNSfind the server
→
3 · The serverHTTP request
→
4 · The responseHTML, CSS, JS
  1. Your browser takes the URL you typed (rivian.com) and asks the operating system "where is this?"
  2. DNS — the "phone book of the internet" — translates rivian.com into a numeric IP address like 23.45.67.89. That's the address of the computer that holds the files.
  3. Your browser sends an HTTP request to that address: "give me the page at /."
  4. The server sends back a response — an HTML file, a stylesheet, a script, images. Your browser parses each one and paints the page you see.
Peek under the hood — see this happen yourself

Open your browser's DevTools (F12 or right-click → Inspect). Go to the Network tab. Reload this page. You'll see every file the browser requested, its size, and how long it took.

The first entry is the HTML you're reading. The others are CSS, JavaScript, fonts, images. That list is web development. When you build a page, you're curating that list.

Concept 03

Frontend vs. backend

The web has two halves. The frontend is what runs in the user's browser — everything they see and touch. The backend is what runs on the server — the logic that stores users, calculates prices, and decides who can see what. A "full-stack developer" does both. Most people start with one.

Runs in the browser

The frontend

Layouts, animations, form validation, button clicks, the whole experience. Written in HTML, CSS, JavaScript — and frameworks like React that organize them.

You'll start here. V1, V2, and V3 are all frontend.

Runs on the server

The backend

The database, the API, the authentication, the payment processing. Written in Node.js, Python, Go, PHP — or one of dozens of others. Comes after you're comfortable with the frontend.

Later. It's where the data lives and the rules are enforced.

Peek under the hood — why the split matters

The frontend is public. Anyone can open DevTools and read your code. So the frontend can never be trusted with secrets — passwords, payment logic, admin rules.

The backend is private. It sits on a server the user can't see. When you log in, the frontend sends your password to the backend; the backend checks it against a database and sends back a token. The frontend then uses that token to prove it's you.

This is why "never trust the client" is the first rule of security. It's also why the two halves exist as separate jobs.

Concept 04

The three core languages

Every browser speaks exactly three languages. Frameworks come and go; these three are the constant. You'll spend your first months with them.

HTML

Structure

The skeleton. Headings, paragraphs, links, images, buttons — the meaning and order of content. If HTML is the frame of a house, CSS is the paint.

CSS

Appearance

Colors, spacing, layout, typography, animation. CSS decides how the skeleton looks on any screen size, from a phone to a widescreen TV.

JavaScript

Behavior

What happens when something is clicked, typed, or scrolled. It reads the HTML, changes the CSS, and talks to servers. It's the only one of the three that "runs."

Peek under the hood — why "just learn a framework" fails

Every framework — React, Vue, Svelte, Angular — compiles down to HTML, CSS, and JavaScript. If you know the framework but not the three languages, you can build an app but you can't debug it, optimize it, or explain it in an interview.

Senior developers can read a framework's source and see the HTML and JS underneath. That's the skill you're building. Frameworks are just a better way to write the three.

Concept 05

Tools & editors

A developer's tools are like a carpenter's bench. You can build with anything, but good tools make it faster and less painful. Here's what every working developer uses in 2026.

VS

VS Code

The default editor. Free, made by Microsoft, runs on every OS, and has an extension for every language. Start here — nothing else is needed.

GH

Git & GitHub

Version control. Every save is a snapshot you can return to. GitHub hosts your code so others can see it — and so you don't lose it. Taught in V1.5.

🔧

Browser DevTools

Built into every browser. Inspect the HTML, change the CSS live, watch the network, debug the JavaScript. You'll use it every day.

⌨

Terminal

The command line. It looks intimidating — it isn't. You'll need about 15 commands forever, and you'll learn them as you go.

AI

AI assistants

Copilot, Cursor, Claude, ChatGPT. Use them as a tutor — ask for explanations, not answers. Taught ethically in V1.5.

▲

Deployment

Netlify, Vercel, Render. Push code, get a live URL. Your first project goes live the week you start V1.

Peek under the hood — nothing else is needed

You don't need a paid plan for anything on this list. You don't need a Mac, or 32GB of RAM, or a $3,000 laptop. A 4-year-old Windows machine with 8GB of RAM will build any of the projects in this curriculum.

What you do need: a stable internet connection, a browser, and 30–60 minutes a day. Everything else is downloadable and free.

Concept 06

Your first setup

Before V1, do these five things. It takes about 45 minutes. After this, you're ready to write code.

  1. Install VS Code — from code.visualstudio.com. Accept the defaults. Install two extensions: Prettier (auto-formats your code) and Live Server (reloads your page every time you save).
  2. Create a GitHub account — from github.com. Free. This is where you'll keep every project forever.
  3. Install Node.js — from nodejs.org. Choose the LTS version. This gives you node and npm in your terminal. You won't use them until V2, but installing them now means you won't stop mid-lesson.
  4. Install Git — from git-scm.com. Accept defaults. This is the "save history" tool taught fully in V1.5.
  5. Create a folder called webdev in your home directory. Every project in this curriculum goes inside it.
Peek under the hood — verify your install

Open a terminal and run:

git --version
node --version
npm --version
code --version

If each prints a version number, you're set. If a command says "not found," reinstall that tool and make sure you checked "Add to PATH" during install.

Concept 07

Why businesses need web development

The web isn't a hobby. It's where almost all commerce, communication, and information now happens. Every company above a certain size has a website, and every website is built and maintained by someone. Here's the range of what that "someone" does.

Direct sales

e-commerce

Shopify, Stripe, custom checkout. One developer can unlock millions in revenue by reducing cart abandonment by 2%.

Cost savings

Internal tools

Every company has a spreadsheet pretending to be software. Replacing it with a proper web app saves hundreds of hours a year.

Trust

Marketing & brand

A slow or broken site costs sales. A fast, accessible site signals legitimacy. This is why this very page you're reading exists.

Reach

Global by default

Deploy once, reach anyone with a browser. No shipping containers, no customs, no warehouse. The margin advantage is enormous.

Peek under the hood — who pays for this work

Every industry in 2026 needs web developers:

Startups hire the first few to build the product. Agencies build for clients. Enterprises build internal systems and public sites. Governments build services. Non-profits build platforms. Individuals build their own businesses.

You do not need to be "creative" or "good at math." You need to be reliable, curious, and comfortable with small failures every day.

Concept 08

Careers & possibilities in 2026

The industry changed shape between 2020 and 2026. AI took over the repetitive parts of coding — boilerplate, syntax lookup, first drafts. What it did not replace is the work of deciding what to build, judging quality, and debugging the strange real-world problems that only humans can understand.

developers worldwide (2026)

+22%

projected growth through 2033

~$110k

median US frontend salary

1995–2010

The page era

Websites were documents. HTML and CSS were enough. "Webmaster" was a job title.

2010–2020

The app era

JavaScript frameworks took over. Web apps started to feel like native desktop apps. React, Vue, Angular, Node.

2020–2024

The framework wars

Next.js, SvelteKit, Astro. Deployment moved to edge networks. Server components became normal.

2024–2026

The AI era

AI wrote the boilerplate. Developers became editors, architects, and quality-gate keepers. Judgment became the scarce skill.

2026 →

What's next

The developers who thrive are the ones who understand the fundamentals deeply enough to guide AI, catch its mistakes, and ship things that actually work.

Peek under the hood — job titles you'll see in 2026

Frontend Developer — builds what users see. HTML, CSS, JavaScript, and one framework. The most common entry point.

Backend Developer — builds the servers and APIs. Node, Python, Go, databases.

Full-Stack Developer — does both. Common at smaller companies and startups.

Design Engineer — hybrid of designer and developer. Increasingly sought-after because they can ship polished UI without waiting for hand-off.

AI Product Engineer — the newest role. Builds features on top of AI models (chat, search, recommendation). Requires strong fundamentals plus API literacy.

Platform / DevOps Engineer — owns deployment, uptime, and infrastructure. Usually comes after a couple years of application development.

You don't need to choose now. Every one of these starts with the same foundation.
